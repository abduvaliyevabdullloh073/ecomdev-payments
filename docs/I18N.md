# Языки интерфейса и API

| Код | Язык | Формат чисел/дат |
| --- | --- | --- |
| `uz` | O‘zbekcha | `uz-UZ` |
| `ru` | Русский | `ru-RU` |
| `en` | English | `en-US` |

Выбор языка находится в верхней панели и внутри каждого диалогового окна. Интерфейс переключается сразу: навигация, таблицы, подписи, подсказки, формы, подтверждения, история, уведомления и ошибки. Значения в открытой форме, выбранные месяц и группа, а также поисковый запрос сохраняются при переключении.

Приоритет языка: поддерживаемый параметр `?lang=ru`, затем сохранённое значение `localStorage`, затем `uz`. Ключ сохранения — `oquv-markaz.language`. После выбора URL обновляется, поэтому ссылку можно передать вместе с языком, месяцем и открытой вкладкой. Неизвестный язык игнорируется; если доступ к хранилищу запрещён, переключение и язык в URL продолжают работать.

Примеры:

```text
http://127.0.0.1:3000/?lang=ru&month=2026-10
http://127.0.0.1:3000/?lang=en&month=2026-10&tab=payments
```

Числа и даты в таблицах, истории и итогах форматируются через `Intl`. Календарные даты отображаются с фиксированным UTC, чтобы день не менялся из-за часового пояса браузера. Валюта остаётся UZS, пересчёта курса нет. В API даты остаются `YYYY-MM-DD`, месяц `YYYY-MM`, суммы — числами. Язык встроенных календарей и числовых полей браузера зависит от самого браузера/ОС; подписи и сообщения приложения локализуются отдельно.

## API

Клиент отправляет `Accept-Language` с выбранным языком. Сервер учитывает региональные варианты и веса, например `ru-RU, en;q=0.8`. Неподдерживаемый язык даёт fallback `uz`. Выбор выполняется для каждого запроса отдельно, без глобального переключения локали Zod.

Локализованные ошибки содержат `Content-Language` и `Vary: Accept-Language`. Машинные `error.code`, имена полей и JSON-структуры сохраняют своё назначение. Дополнительный `messageKey` позволяет перевести уже показанную ошибку при смене языка без повторной отправки платежа.

```json
{
  "error": {
    "code": "STUDENT_NOT_FOUND",
    "message": "Ученик не найден.",
    "messageKey": "apiStudentNotFound"
  }
}
```

## Где редактировать переводы

Общий модуль — `src/shared/i18n.ts`. Каждому ключу соответствует тройка строк: **узбекский, русский, английский**. TypeScript проверяет наличие трёх значений, тесты проверяют заполненность строк и одинаковые параметры `{name}`, `{amount}`, `{count}` во всех языках.

Статические элементы HTML помечены `data-i18n`; атрибуты используют `data-i18n-placeholder`, `data-i18n-aria-label` и аналогичные метки. Динамические сообщения проходят через `translate`. Пользовательские имена и группы вставляются как текст с экранированием HTML.

Для четвёртого языка расширьте список `languages`, `locales`, `languageColumn` и тип кортежа переводов, добавьте значения ко всем ключам и новый вариант во все элементы `[data-language-control]` в `public/index.html`. Затем выполните `npm run check` и `npm run test:e2e`.
