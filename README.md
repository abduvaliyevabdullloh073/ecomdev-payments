# Учёт. — оплаты учебного центра

Тестовое задание Ecomdev: REST API и адаптивная веб-страница, **вариант Б**. Можно добавлять, изменять и удалять учеников, вносить платежи, смотреть историю и получать должников за календарный месяц.

Стек: **Python 3.12+, FastAPI, SQLite, HTML/CSS/JavaScript**. Бэкенд и интерфейс обслуживаются одним приложением; сборка фронтенда, отдельный сервер БД и Node.js для запуска не нужны. Проверено на Python 3.12.14. Для инструкций на узбекском см. [BOSHLASH_UZ.md](BOSHLASH_UZ.md).

## Запуск с нуля

Установите Python 3.12 или новее. Скачайте проект либо клонируйте уже опубликованный репозиторий. Откройте терминал **в каталоге проекта**, где находится этот README.

```bash
git clone https://github.com/abduvaliyevabdullloh073/ecomdev-payments.git
cd ecomdev-payments
```

Без Git можно выбрать **Code → Download ZIP** на странице репозитория и распаковать архив.

### Windows: PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m app
```

Если используется другая установленная версия Python 3.12+, замените `py -3.12` на `python`. Активировать окружение и менять ExecutionPolicy не требуется.

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app
```

На Linux при отсутствии модуля `venv` установите соответствующий пакет вашей ОС, например `python3-venv` в Ubuntu.

- Интерфейс: **http://127.0.0.1:8000**.
- Swagger с возможностью выполнять запросы: **http://127.0.0.1:8000/docs**.
- OpenAPI: **http://127.0.0.1:8000/openapi.json**.
- Проверка доступности: **http://127.0.0.1:8000/health**.
- Остановка: `Ctrl+C`.

База и её каталог создаются автоматически при первом запуске. По умолчанию база пустая. Данные сохраняются после перезапуска; повторный запуск не очищает таблицы.

### Демо-данные — по желанию

В отдельном терминале из каталога проекта:

```bash
# Linux / macOS
.venv/bin/python -m app.seed
```

```powershell
# Windows
.\.venv\Scripts\python.exe -m app.seed
```

Добавляются 6 **вымышленных** учеников и 5 платежей за текущий месяц Ташкента: есть неоплаченный тариф, частичные оплаты, полная оплата и переплата. Должников — 4, общий долг — `1280000.00` сум. Если ученики уже есть, команда ничего не меняет. Демо-наполнение никогда не запускается автоматически. После команды обновите страницу.

### Настройки

| Переменная окружения | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_PATH` | `data/payments.sqlite3` внутри проекта | Путь к SQLite; относительный путь считается от рабочего каталога |

Текущие дата и месяц для интерфейса приходят с сервера в `Asia/Tashkent` (UTC+05:00). Сами даты платежей хранятся как календарные даты без времени.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| `GET` | `/students` | Массив учеников по возрастанию ID |
| `POST` | `/students` | Созданный ученик, `201` |
| `GET` | `/students/{id}` | Ученик, `200` |
| `PUT` | `/students/{id}` | Полная замена всех четырёх полей, `200` |
| `PATCH` | `/students/{id}` | Частичное изменение, `200` |
| `DELETE` | `/students/{id}` | Удаление ученика **вместе с платежами**, `204`, без тела |
| `GET` | `/students/{id}/payments` | Все платежи ученика; сначала новые по дате, затем по ID |
| `POST` | `/students/{id}/payments` | Созданный платёж, `201` |
| `GET` | `/debtors?month=2026-10` | Отчёт и список должников, `200` |

Для несуществующего ученика, включая запросы его платежей: `404`. Ошибки входных данных: `422`. `month` обязателен, имеет ровно формат `YYYY-MM`; поддерживаются годы 0001–9999. Операции с неверным ID, например `0` или `abc`, возвращают `422`.

### Примеры запросов

Следующие команды — для bash. В Windows те же запросы удобно выполнить через `/docs`, нажав **Try it out**. Для чистой базы первый ученик получит ID `1`; для непустой используйте ID из ответа создания.

```bash
curl -X POST http://127.0.0.1:8000/students \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ali Valiyev","phone":"+998901234567","group":"Python-01","monthly_fee":"650000.00"}'

curl -X POST http://127.0.0.1:8000/students/1/payments \
  -H 'Content-Type: application/json' \
  -d '{"amount":"250000.00","date":"2026-10-21"}'

curl 'http://127.0.0.1:8000/debtors?month=2026-10'
```

После этих двух запросов в пустой базе ответ:

```json
{
  "month": "2026-10",
  "student_count": 1,
  "debtor_count": 1,
  "total_expected": "650000.00",
  "total_paid": "250000.00",
  "total_debt": "400000.00",
  "debtors": [
    {
      "student_id": 1,
      "name": "Ali Valiyev",
      "phone": "+998901234567",
      "group": "Python-01",
      "monthly_fee": "650000.00",
      "paid": "250000.00",
      "debt": "400000.00"
    }
  ]
}
```

Пример частичного изменения: `PATCH /students/1` с телом `{"monthly_fee":"700000.00"}`. Пустой PATCH, явный `null` и неизвестные поля отклоняются. Формат ошибки валидации:

```json
{
  "detail": "Проверьте поля запроса.",
  "errors": [{"field": "body.amount", "message": "Value error, Некорректная сумма."}]
}
```

## Правила расчёта и принятые решения

1. Для каждого ученика: **долг = max(месячный тариф − сумма его платежей в месяце, 0)**. В `debtors` попадают только положительные долги; сортировка — по долгу убывающе, затем по ID. Ученик без платежей обязан попасть в список при положительном тарифе.
2. Учитывается дата платежа, включая первый и последний дни месяца. Платежи соседних месяцев не влияют на результат. Разрешены исторические и будущие даты: задание не задаёт дополнительного ограничения.
3. Переплата не переносится на следующий месяц и не закрывает долг другого ученика. Поэтому `total_debt` — сумма положительных индивидуальных долгов, а не просто `total_expected - total_paid`.
4. Валюта — UZS. В API деньги возвращаются строками с двумя знаками после точки. На вход допустимы строка или JSON-число; для точности рекомендуется строка. В SQLite — целое число тийинов, расчёты — целочисленные, преобразования — `Decimal`. `float` в расчёте долга не используется.
5. Тариф — от `0.00` до `1000000000.00`, один платёж — от `0.01` до `1000000000.00`. Более двух значащих дробных знаков, `NaN`, бесконечность и булевы значения отклоняются. Нулевой тариф разрешён для бесплатного обучения. Итоги могут превышать лимит одной операции.
6. В задании нет истории тарифов и дат зачисления: текущий тариф применяется ко всем выбранным месяцам, включая прошлые. Изменение тарифа пересчитывает исторический отчёт; новый ученик виден и при выборе прошлого месяца. Это осознанная граница простой модели, не расчёт накопленного баланса.
7. Телефон содержит 7–15 цифр; разрешены `+` в начале, пробелы, скобки и дефисы. Уникальность телефона не требуется: один контакт может принадлежать родителю нескольких учеников.
8. Удаление ученика каскадно удаляет его платежи; интерфейс требует подтверждения. Двойная отправка формы блокируется. Автоматических повторов POST нет, поскольку отдельный ключ идемпотентности в этой версии не реализован.

## Архитектура

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| HTTP | `app/main.py` | Маршруты, зависимости, статические файлы, HTTP-ошибки |
| Вход и выход | `app/schemas.py` | Валидация полей, денег, телефона и календарных дат, формат JSON |
| Прикладная логика и SQL | `app/service.py` | CRUD, транзакции и месячный отчёт одним агрегирующим запросом |
| Хранение | `app/database.py`, `app/schema.sql` | Соединения, внешние ключи, WAL, начальная версия схемы |
| Интерфейс | `app/static/` | Мобильная страница без сборки и сторонних CDN |
| Настройки и демо | `app/config.py`, `app/seed.py` | Путь БД, дата Ташкента, явное безопасное демо-наполнение |

Для двух небольших таблиц прямой параметризованный SQL проще дополнительного ORM и слоя абстрактных репозиториев. Пользовательские данные не подставляются в текст SQL. Каждому запросу выделяется отдельное соединение, запись завершается транзакцией, внешний ключ включается на каждом соединении. База создаётся в lifecycle приложения, при импорте модулей записи на диск нет.

В интерфейсе пользовательский текст добавляется через `textContent`, без HTML-интерполяции; есть CSP, состояния загрузки и ошибки сети. Ответ старого запроса не перезапишет данные после быстрого переключения месяца.

Это локальное тестовое приложение без авторизации. Для реального доступа сотрудников через интернет сначала нужны авторизация и разграничение доступа; они не входят в задание. Рабочая база, виртуальное окружение и секреты исключены из Git.
