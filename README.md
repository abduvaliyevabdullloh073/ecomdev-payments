# Ecomdev — учёт оплат учебного центра

Тестовое задание Ecomdev: ученики, оплаты и должники за выбранный месяц. Реализованы все пункты частей 1–3; выбран **вариант Б — адаптивная веб-страница**. Интерфейс на узбекском, русском и английском с переключателем языка; документация для проверяющего на русском. [O‘zbekcha ishga tushirish yo‘riqnomasi](README.uz.md).

**Стек:** Node.js 24, TypeScript, Express 5, Zod, SQLite (`node:sqlite`), HTML/CSS и TypeScript в браузере. Отдельный сервер БД, Telegram-токен и платные API не нужны.

**Репозиторий:** [abduvaliyevabdullloh073/ecomdev-payments](https://github.com/abduvaliyevabdullloh073/ecomdev-payments). Актуальная версия в ветке `main` — Node.js/TypeScript; предыдущая Python-версия сохранена в истории Git.

## Запуск с нуля

Установите [Node.js 24 LTS](https://nodejs.org/en/download) версии **24.15 или новее в ветке 24.x**. Проверьте `node --version`. Команды выполняются в каталоге проекта и одинаковы для Windows PowerShell, macOS и Linux.

Скачайте исходники через **Code → Download ZIP** или клонируйте репозиторий:

```sh
git clone https://github.com/abduvaliyevabdullloh073/ecomdev-payments.git
cd ecomdev-payments
```

Затем установите зависимости и запустите приложение:

```sh
npm ci
npm run setup
npm run build
npm start
```

Откройте **http://127.0.0.1:3000**. `setup` создаёт `.env`, если его ещё нет. При первом запуске автоматически создаются каталог `data/`, SQLite-файл и таблицы. По умолчанию база пустая: добавьте ученика кнопкой «+ O‘quvchi», затем внесите оплату. Остановить сервер: `Ctrl+C`. Повторный запуск сохраняет данные.

Чтобы увидеть демонстрацию, выполните `npm run seed` перед `npm start` (или при остановленном сервере). Команда добавит 8 вымышленных учеников и 7 оплат за текущий месяц по часовому поясу приложения. Если ученики уже существуют, seed ничего не меняет; повторный запуск не дублирует данные. Для отдельной демонстрационной базы задайте другой `DATABASE_PATH` в `.env`.

Для разработки: `npm run dev`. Команда собирает браузерную часть, затем перезапускает сервер при изменении серверного TypeScript. После изменения клиентского кода/CSS запустите `npm run build` и обновите страницу.

## Правила расчёта

- Валюта — UZS; API принимает суммы **числом**, до 2 знаков после точки, максимум `100000000` за одну запись. Месячная сумма может быть `0`; платёж строго больше `0`. В БД деньги хранятся целым количеством сотых долей: `0.1 + 0.2` учитывается точно как `0.3`.
- `paid` — сумма оплат ученика с датами внутри выбранного календарного месяца; `debt = max(monthlyFee − paid, 0)`. Отсутствие оплат даёт полный долг. Полностью оплатившие, переплатившие и ученики с нулевым тарифом в должники не попадают.
- Частичные оплаты складываются. Оплаты соседних месяцев исключаются. Переплата автоматически не переносится на следующий месяц; прошлые долги тоже не прибавляются к новому месяцу.
- Дата строго `YYYY-MM-DD`, месяц строго `YYYY-MM`; несуществующие даты (например `2026-02-29`) отклоняются. Разрешены прошлые и будущие даты в диапазоне лет `1000–9999`. Отчёт использует дату оплаты, а не момент создания записи.
- Текущий день веб-интерфейс получает от сервера в `APP_TIME_ZONE` (по умолчанию `Asia/Tashkent`), независимо от часового пояса браузера. Месяц отчёта можно выбрать вручную.
- В задании нет истории тарифов и даты начала обучения: каждый отчёт использует **текущий тариф и текущий список учеников**, включая отчёты за прошлые месяцы. Изменение тарифа пересчитывает их. Это явно указано в форме редактирования.
- `DELETE /students/:id` удаляет ученика **вместе со всеми его оплатами** (`ON DELETE CASCADE`); интерфейс требует отдельного подтверждения. Исторические отчёты после удаления изменяются. Платежи отдельно не редактируются и не удаляются — этого нет в задании.
- Это локальный однопользовательский прототип без авторизации; по умолчанию сервер слушает `127.0.0.1`. Для эксплуатации несколькими администраторами нужны улучшения ниже.

## API

Все JSON-ответы используют UTF-8. Создание — `201`, чтение/изменение — `200`, удаление — `204`. Для `POST`, `PUT`, `PATCH` нужен `Content-Type: application/json`; максимальный размер тела — 16 КБ. Неизвестные поля в JSON отклоняются. API доступно по тому же адресу, что и страница, без префикса `/api`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка сервера и доступности БД |
| GET | `/config` | Текущий календарный день, часовой пояс, валюта |
| GET | `/students` | `{ "students": [...] }` |
| POST | `/students` | Создание ученика; ответ — объект ученика и заголовок `Location` |
| GET | `/students/:id` | Объект ученика |
| PATCH | `/students/:id` | Частичное изменение, хотя бы одно поле |
| PUT | `/students/:id` | Полная замена четырёх полей ученика |
| DELETE | `/students/:id` | Удалить ученика и его оплаты |
| POST | `/payments` | `{ studentId, amount, date }`, ответ — объект оплаты |
| GET | `/students/:id/payments` | `{ "payments": [...] }` за все месяцы, только для этого ученика |
| POST | `/students/:id/payments` | Альтернативная запись оплаты: `{ amount, date }` |
| GET | `/payments` | Все оплаты; необязательные фильтры `?studentId=1&month=2026-10` |
| GET | `/debtors?month=2026-10` | Должники и общий долг; `month` обязателен |
| GET | `/summary?month=2026-10` | Итоги выбранного месяца; `month` обязателен |

Создать ученика:

```json
{
  "name": "Aziz Karimov",
  "phone": "+998 90 123 45 67",
  "group": "Node.js N-01",
  "monthlyFee": 850000
}
```

Внести частичную оплату:

```json
{ "studentId": 1, "amount": 400000, "date": "2026-10-10" }
```

Ответ `GET /debtors?month=2026-10` для такого ученика:

```json
{
  "month": "2026-10",
  "count": 1,
  "totalDebt": 450000,
  "debtors": [{
    "studentId": 1, "name": "Aziz Karimov", "phone": "+998 90 123 45 67",
    "group": "Node.js N-01", "monthlyFee": 850000, "paid": 400000, "debt": 450000
  }]
}
```

Проверка из PowerShell:

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:3000/students'
Invoke-RestMethod -Uri 'http://127.0.0.1:3000/debtors?month=2026-10'
```

Готовые запросы для REST Client: [docs/api.http](docs/api.http).

В `/summary` поле `expected` — сумма тарифов; `collected` — вся сумма платежей месяца, включая переплаты; `applied` — сумма `min(paid, monthlyFee)` по ученикам; `outstanding` — непогашенный долг; `surplus` — переплата. Диаграмма использует `applied / expected`, поэтому не превышает 100%. При нулевом плане отображается 0% и пояснение.

Ошибка имеет вид:

```json
{ "error": { "code": "STUDENT_NOT_FOUND", "message": "O‘quvchi topilmadi." } }
```

Коды: `400 VALIDATION_ERROR` (с массивом `details`) / `400 INVALID_JSON`, `404 STUDENT_NOT_FOUND` / `NOT_FOUND`, `403 ORIGIN_REJECTED`, `413 BODY_TOO_LARGE`, `415 UNSUPPORTED_MEDIA_TYPE`, `500 INTERNAL_ERROR`. Неверные ID и повторяющиеся query-параметры отклоняются. SQL использует связанные параметры; текст пользователя экранируется в интерфейсе. Межсайтовые запросы на изменение отклоняются по `Origin`, CSP запрещает внешние скрипты. Эти меры не заменяют авторизацию.

## Проверки

```sh
npm run check
```

Команда выполняет строгую проверку типов сервера, браузера и тестов, **28 автоматических тестов** домена/API/i18n, затем production-сборку. API тестируется реальными HTTP-запросами с изолированной SQLite-базой. Проверяются CRUD, валидация, частичные и полные платежи, переплаты, соседние месяцы, високосные даты, десятичные суммы, каскадное удаление и сохранность БД после повторного открытия.

Проверки интерфейса на desktop и mobile:

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

Девять сценариев выполняются в двух размерах экрана (всего 18 запусков): полный рабочий цикл, фильтры/экранирование/размер страницы, ошибки и восстановление, операции на каждом из трёх языков, сохранение выбора, fallback и недоступное хранилище. Проверяются также сохранность полей и перевод уже показанных ошибок при переключении языка. Тестовый сервер запускается автоматически на порту 3127 и использует отдельную временную БД. Основная база не затрагивается. На Linux без библиотек браузера используйте `npx playwright install --with-deps chromium`.

| --- | --- | --- |

## Архитектура

HTTP и валидация отделены от бизнес-операций и SQL. Один процесс обслуживает API и статическую страницу; миграция выполняется до открытия HTTP-порта.

| Файл/каталог | Ответственность |
| --- | --- |
| `src/server/app.ts` | Маршруты Express, JSON, безопасность, единый формат ошибок |
| `src/server/domain.ts` | DTO, Zod-схемы, деньги, даты и границы месяца |
| `src/server/service.ts` | Операции с учениками/оплатами, обработка отсутствующего ученика |
| `src/server/repository.ts` | SQL с параметрами, агрегирование отчёта в целых числах |
| `src/server/database.ts`, `migrations/` | Соединение, внешние ключи, WAL и версия схемы |
| `src/client/app.ts`, `public/` | Адаптивный интерфейс, формы, таблицы и обработка загрузки/ошибок |
| `src/shared/i18n.ts` | Общий типизированный каталог переводов, форматирование и ключи ошибок |
| `tests/` | Доменные, HTTP и браузерные проверки |

Нативный SQLite выбран для простой установки, без компиляции стороннего драйвера. Синхронные запросы подходят масштабу мини-приложения; для большого потока запросов нужен другой подход. Документация: [Node.js 24 SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Express 5](https://expressjs.com/en/5x/guide/error-handling/).
